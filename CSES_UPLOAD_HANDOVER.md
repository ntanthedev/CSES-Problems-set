Upload all **CSES problems** (statements, test data, editorials, images, and
Vietnamese translations) onto a self-hosted online judge.

- **Target OJ:** `https://oj.thptchuyenhatinh.edu.vn` — a fork of **VNOJ/DMOJ**
  (repo: `ntanthedev/CHT-oj`).
- **Content source:** `ntanthedev/CSES-Problems-set` (~2.9 GB, 400 problems).
- **Operator:** the OJ **superuser** (`ntannn`), with **no 2FA**.
- **Important constraint:** the operator has **no SSH** to the server (it was handed
  to someone else; Tailscale/port limits). So everything is driven **over HTTP from
  the operator's own machine** using an admin login — *not* via `manage.py`.

The deliverable that does this is **`cses_http_upload.py`** (the operator runs it
locally, often renamed to `upload.py`).

## 3. Source repo layout (`CSES-Problems-set`)

```
<Category>/<ID>_<Name>/
    statement_en.md      # problem statement (English); time/memory limits inside it
    statement_vi.md      # Vietnamese translation (generated by subagents; may be absent)
    analysis_en.md       # editorial (English)
    analysis_vi.md       # editorial (Vietnamese; optional)
    solution.cpp         # reference solution (not uploaded)
    tests_<ID>.zip       # test data: N.in / N.out files at the zip root
    <64-hex-hash>        # image files (PNG), no extension, referenced by hash in md
```

Categories (folder names, all start with a numeric problem ID inside):

Advanced Techniques, Counting Problems, Additional Problems I/II, Advanced Graph

**Statement format** (consistent across all 400):
```
# 1068 - Weird Algorithm

# Example
```
- Inline math: `$...$`  ·  Display math: `$$...$$`
- Time limits observed: all `1.00 s`. Memory: `128 MB` or `512 MB`.

## 4. Key VNOJ/DMOJ facts discovered (so you don't re-derive them)

All confirmed by reading the `ntanthedev/CHT-oj` source.

### Auth
- Login: `POST /accounts/login/` with `username`, `password`, `csrfmiddlewaretoken`,
  and a `Referer` header (Django strict-referer on HTTPS). A `requests.Session`
  holds the `sessionid` cookie afterwards. **2FA is not handled.**
- The same session authorizes the front-end **and** `/admin/`.

### Create problem (front-end) — `POST /problems/create`
- View `ProblemCreate`, form `ProblemEditForm`. Requires perm `judge.add_problem`
  (superuser passes). Distinct from `/problems/suggest` (for normal users).
- **`is_public` is removed** from this form for global problems → created problems
  are **hidden by default** (publish later, see Publish).
- The view auto-adds the creator to curators and sets `allowed_languages` to all
  runtimes with `include_in_problem=True`.
- Fields (form input names = model field names): `code`, `name`, `description`
  (markdown), `time_limit` (seconds, float), `memory_limit` (**KB**), `points`,
  `partial` (checkbox; default ON → we turn OFF for CSES binary scoring), `source`,
  `types` (pk; **Select2, options in page HTML**), `group` (pk; Select2),
  `submission_source_visibility_mode`, `testcase_visibility_mode`, `testers`,
  `statement_file`.
- **Labels are Vietnamese.** Group dropdown contains `Chưa phân loại`, **`CSES`**,
  etc. We match by visible label → use group **CSES**.
- `testcase_visibility_mode` values: **`A` = always visible ("Có thể xem")**,
  `C` = visible out-of-contest, `O` = authors only (site default). We use `A`.

### Test data — `POST /problem/<code>/test_data`
- View `ProblemDataView`. `multipart/form-data`.
- Data form prefix **`problem-data`**: `problem-data-zipfile` (file),
  `problem-data-checker` = `standard` (token compare, matches CSES),
  `problem-data-grader` = `standard`, `problem-data-checker_type` = `default`,
  `problem-data-io_method` = `standard`, plus empty `*-checker_args`,
  `*-grader_args`, `*-output_limit`, `*-io_input_file`, `*-io_output_file`.
- Cases formset prefix **`cases`**: management keys
  `cases-TOTAL_FORMS`/`INITIAL_FORMS`/`MIN_NUM_FORMS`/`MAX_NUM_FORMS`; per row
  `cases-<i>-id` (empty), `-order`, `-type`=`C`, `-input_file`=`N.in`,
  `-output_file`=`N.out`, `-points`=`1`, and `-checker`/`-checker_args`/
  `-generator_args` empty. `is_pretest`/`public`/`DELETE` omitted (= False).
- Server-side init.yml is generated by `ProblemDataCompiler` (same as the admin
  "Problem Data" page). Each case worth 1 point; with `partial=False` the problem
  is all-or-nothing (CSES-style).

### Editorial (Solution) — front-end `POST /problem/<code>/edit`
- `Solution` is an **admin-inline-only model**, BUT `ProblemEdit` (front-end
  `/problem/<code>/edit`, template `problem/editor.html`) renders a **solution
  formset** in the same `<form>` as the main edit form. We use the front-end (much
  simpler than admin).
- Solution fields: `is_public`, `publish_on` (**`<input type=date>` → `YYYY-MM-DD`**),
  `authors` (optional, heavy-select2 → leave empty), `content` (markdown).
- Formset prefix **`solution`** (Django accessor name; O2O `related_name='solution'`).
- Strategy: GET the edit form → keep every field via `form_defaults` → fill one
  solution row → POST. `add_editorial()` does this.

### Translation (ProblemTranslation) — admin `POST /admin/judge/problem/<pk>/change/`
- `ProblemTranslation` is **admin-inline-only** (`related_name='translations'`,
  `unique_together=(problem, language)`). NOT on the front-end edit page.
- Resolve pk via `GET /admin/judge/problem/?q=<code>` (admin `search_fields`
  includes `code`).
- Translation fields: `language` (choices from `settings.LANGUAGES`: `en`, `vi`, …),
  `name` (translated title), `description` (markdown).
- Formset prefix **`translations`**.
- **DANGER:** the admin problem form has many fields incl. the **`allowed_languages`
  M2M multi-select**. A naive form re-submit that keeps only one selected option
  would **wipe the other submission languages**. The tool uses a *multi-select-aware*
  payload builder (`form_payload_multi`) that preserves **all** selected options.
  `add_translation()` is the riskiest piece — **test on 1 problem and verify
  `allowed_languages` survives** (see §9).

### Publish (bulk) — admin action
- `GET/POST /admin/judge/problem/?q=cses_` with action
  `make_public_and_update_publish_date`, `select_across=1` → publishes **all**
  `cses_*` problems at once (sets `is_public=True`, `date=now`, rescore).

### Markdown / math (critical)
- Renderer: `markdown2` with the `latex` extra. Its regex is
  `(~.*?~)|(\$\$.*?\$\$)` → **inline math = `~...~`**, **display math = `$$...$$`**.
  CSES uses `$...$` inline, so the tool **converts inline `$...$` → `~...~`** and
  leaves `$$...$$` alone (`convert_math()`), skipping code fences/spans and `\$`.
- Renderer also bumps headings **+2 levels** (`inc_header`). We additionally
  **down-shift section headers `#` → `##`** so they render a notch smaller.
- The `problem` markdown style has **`safe_mode: False`** → raw HTML is allowed.
  The bleach whitelist allows `<center>`, `<div>`, `<img>` (incl. `align`/`style`),
  so **image centering with `<center><img ...></center>` works**.

### Images — `POST /martor/upload-image`
- View `martor_image_uploader` (name `martor_image_uploader`). Requires header
  **`X-Requested-With: XMLHttpRequest`**, `csrfmiddlewaretoken`, and the file field
  **`markdown-image-upload`**.
- Staff users (we are) → stored in **local media** (permanent URL). Returns JSON with
  a `link`. The tool uploads each hash file once, then rewrites `![](hash)` to a
  centered `<img>` pointing at the returned URL.

## 5. The tool: `cses_http_upload.py`

Pure-Python, runs on the operator's machine. **Dependencies:**
`pip install requests beautifulsoup4 lxml` (lxml strongly recommended — the create
page embeds a Martor editor whose HTML confuses the stdlib parser).

### Per-problem workflow
For each `<Category>/<ID>_<Name>/`:
1. Parse limits from **`statement_en.md`** (stable English labels) → `time_limit`,
   `memory_limit`. Build the body from the chosen language file (`--lang`/`--vi`),
   **stripping the redundant time/memory bullet lines** (language-agnostic) and the
   title H1, **down-shifting headers**, and **converting math**.
2. **Upload & rewrite images** (`process_images`): each `![](hash)` → upload the PNG
   → `<center><img src="…"></center>` (cached per run).
3. **Create** the problem (front-end) if new; or **`update_problem`** if it exists
   and `--overwrite` (re-pushes description/limits/points/visibility).
4. **Upload test data** (zip + cases formset) on create or `--overwrite`.
5. **Editorial** (`--with-editorial`): `analysis_<lang>.md` → front-end solution
   formset. `--editorial-public` makes it visible.
6. **Translation** (`--bilingual`): the *other* language's statement → admin
   `ProblemTranslation` (so Vietnamese in `description` + English as an `en`
   translation, or vice-versa).
7. After the loop, **bulk-publish** all `cses_*` (unless `--no-publish`).

Re-running is safe/idempotent: existing problems are skipped unless `--overwrite`;
translations update the matching-language row instead of duplicating.

### CLI reference
```
--root PATH              (required) path to CSES-Problems-set; use "." if the
                         script sits inside the repo
--site URL               default https://oj.thptchuyenhatinh.edu.vn
                         (must be a FULL https:// URL; just omit it to use default)
--user NAME              admin username (required for a real run)
--password PW            prompted securely if omitted (preferred)
--lang CODE              statement language to prefer; falls back to en
--vi                     shortcut for --lang vi
--code-prefix STR        default "cses_"  (-> cses_1068)
--points FLOAT           default 1.0 (VNOJ scale 0–2)
--partial                allow partial scoring (default OFF = CSES binary)
--group NAME             problem group label; default "CSES"
--type-from-category     map CSES category to a problem type (default on)
--default-type NAME      fallback type; default "Chưa phân loại"
--testcase-visibility {visible|out-contest|authors}   default "visible" (= "Có thể xem")
--with-editorial         upload analysis_<lang>.md as the editorial (Solution)
--editorial-public       make the editorial publicly visible (default hidden)
--bilingual              also add the other language as a ProblemTranslation (admin)
--no-publish             do NOT bulk-publish at the end
--overwrite              refresh existing problems (statement/limits + test data)
--only ID [ID ...]       restrict to specific CSES IDs
--sleep SECONDS          delay between problems (default 0.5)
--dry-run                parse locally and report; no network
--debug                  on "form not found", print status/title and save the page
```

### Decisions baked in (operator's choices)
- **Points:** 1.0/problem · **Scoring:** `partial=False`, each case 1 pt (binary AC).
- **Group:** `CSES` · **Testcase visibility:** `visible` ("Có thể xem").
- **Code:** `cses_<ID>`.
- **Language:** bilingual — **Vietnamese is the main `description`**, **English is an
  `en` translation** (`--vi --bilingual`). Problem titles stay English (only the body
  is translated).
- **Editorial:** uploaded and **public** (`--with-editorial --editorial-public`).
- **Auto-publish:** yes.

### The exact intended command (full run)
```bash
python upload.py --user ntannn --root . \
    --vi --bilingual --with-editorial --editorial-public
```
Fix the early test problems:
```bash
python upload.py --user ntannn --root . --only 1068 1083 \
    --vi --bilingual --with-editorial --editorial-public --overwrite
```

### Internal design notes (for whoever edits the script)
- `form_defaults(form)` → dict of name→value for a single-value form (front-end).
- `form_payload_multi(form)` → **list of (name,value) tuples**, keeps ALL selected
  options of multi-selects; used for the admin form. Helpers `items_get`/`items_set`.
- `convert_math`, `downshift_headers`, `LIMIT_LINE_RE`, `IMG_RE` handle text.
- CSRF: every POST GETs a fresh page for the token and sets a `Referer` header.
- Success is detected by a 302 redirect (`allow_redirects=False`); a 200 means the
  form re-rendered with errors → `show_errors()` extracts them; `--debug` dumps the
  page to `debug_*.html`.

## 6. Translation generation (subagents)

The tool does **not** translate; it only consumes `statement_vi.md` /
`analysis_vi.md` if present (else falls back to English). Generate them with
subagents using a **fixed prompt + a glossary + a validation pass** (this beats
"spamming" many uncoordinated agents).

**Prompt to give each translator subagent** (writes `<name>_vi.md` next to `_en`):
```
You are a competitive-programming translator. Translate the CSES statement/editorial
from English to Vietnamese, writing <name>_vi.md in the same folder as the _en file.

HARD RULES (violations corrupt the problem):
1. Translate PROSE ONLY. Copy verbatim, unchanged:
   - All math: $...$, $$...$$, ~...~ (incl. \le, \frac, \rightarrow, spacing, indices).
   - All code ```...``` and inline `...`, including sample input/output.
   - All numbers, variables, function names, symbols, links, images ![](...).
   - Markdown structure: heading count/levels (#), bullets, tables, bold/italic.
2. Keep section headers in place; translate their titles:
   Input→Dữ liệu vào, Output→Kết quả, Constraints→Giới hạn, Example→Ví dụ,
   Explanation→Giải thích. Do not add/remove sections.
3. Use a CONSISTENT glossary: array→mảng, string→xâu, prefix sum→tổng tiền tố,
   segment tree→cây phân đoạn, binary search→tìm kiếm nhị phân,
   dynamic programming→quy hoạch động, graph→đồ thị, node/vertex→đỉnh, edge→cạnh,
   tree→cây, subtree→cây con, weight→trọng số, query→truy vấn,
   time/space complexity→độ phức tạp thời gian/bộ nhớ, test case→bộ test.
4. Natural problem-statement tone; neutral address. No commentary, no summary, no
   dropped sentences.
5. Output ONLY the translated Markdown — no explanations, no ```markdown wrapper.

SELF-CHECK before writing: counts of $...$, $$...$$, ~...~ and ``` blocks must equal
the source. If they differ, fix and re-check.
```
**Validation:** for each pair, compare counts of `$...$`, `$$...$$`, inline code, and
code fences between `_en` and `_vi`; re-translate any mismatch. (A small
`validate_vi.py` was discussed but not built — optional to add.)

> Image note: subagents should **leave `![](hash)` untouched**. The uploader uploads
> the image and centers it for both languages — subagents must NOT add `<div>`/`<center>`.

## 7. Gotchas / troubleshooting

- **`--site ...` → `MissingSchema: No scheme supplied`**: `...` was a placeholder.
  Omit `--site` (uses the default) or pass the full `https://…` URL.
- **"Could not find the create-problem form (permission denied?)"**: the account
  lacks `judge.add_problem`, or the page didn't parse. Ensure superuser; install
  `lxml`; run with `--debug` (it saves `debug_create.html`).
- **"Trường này là bắt buộc" (field required) on create**: group/type sent empty
  because of a label mismatch. The tool now matches Vietnamese labels and never
  sends empty; ensure the group `CSES` exists.
- **Memory shows 256 MB / limit lines still in the statement**: caused by translated
  limit labels in `statement_vi.md`. Fixed — limits are read from `statement_en.md`
  and limit bullets are stripped language-agnostically. Re-run affected problems with
  `--overwrite`.
- **3 corrupt test zips** (`2133`, `3410`, `3411`): re-download those test sets.
- **Translation step risk**: after the first bilingual run, verify in the UI that the
  problem still lists all submission languages (admin form M2M preservation). If
  missing, stop and report the `debug_admin_change_post.html` dump.

## 9. Post-run verification checklist (do this after the first real problem)

Open the problem on the OJ and confirm:
- [ ] Body language correct (Vietnamese primary); switching UI to English shows the
      English translation.
- [ ] Side panel shows the right **time/memory** (e.g. 1.0 s / 512 M) and they match
      the statement (no duplicate limit lines in the body).
- [ ] Section headers render one level smaller (`##`).
- [ ] Inline math renders (no literal `$` signs).
- [ ] **Submission languages** (C, C++, Python, …) are all present — confirms the
      admin translation step didn't wipe `allowed_languages`.
- [ ] Editorial appears under "Đọc lời giải" / Editorial (public).
- [ ] Image problems (e.g. **1625**) show the image, centered.
- [ ] Group is **CSES**; testcase visibility is **"Có thể xem"**; code is `cses_<ID>`.
- [ ] Submitting the reference solution gets **AC** (sanity-check the test data).
